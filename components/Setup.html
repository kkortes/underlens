Add it to a repo

Four steps and three files. Most repos need to change only the rules.

1 Write the three files

bunx @ape-egg/underlens init

This writes the three files below into your repo and leaves any that already exist alone.

underlens.config.js

Who reviews and who judges, one string each naming the harness and, if you like, the model: 'claude' runs Claude Code's default, 'claude-opus-5-5' runs Opus 5.5. The defaults are Claude for both. Every model string.

underlens-quality-control.md

Your rules. Replace the starter set with what your team actually holds code to, numbered, one decidable claim each.

.github/workflows/underlens.yml

The triggers, the token's permissions and one line that calls Underlens with your harness secrets. The triggers decide when PRs are reviewed: the template reviews once a night at the cron hour, in UTC. Add opened and reopened to review each PR as it opens, or drop schedule to review only when you ask. Keep edited and closed: they act on Agree and Disagree, and clean up after a closed PR. GitHub only hands secrets to a called workflow that you pass them to, one line each; keep the lines for the harnesses you use.

2 Add a secret per harness

One per harness in underlens.config.js, however many of its models you use. See the instructions for each one. With the default config, that's:

claude setup-token gh secret set CLAUDE_CODE_OAUTH_TOKEN

3 Let workflows open pull requests

The fixes arrive as PRs, and GitHub only lets workflows open PRs once you allow it: Settings → Actions → General → "Allow GitHub Actions to create and approve pull requests". Or from the repo folder:

gh api -X PUT repos/{owner}/{repo}/actions/permissions/workflow -F can_approve_pull_request_reviews=true

4 Commit, then validate before a real run

Push the three files to your default branch, then run the workflow by hand on that branch: Actions → Underlens → Run workflow, with the default branch under "Use workflow from", or from the repo folder:

gh workflow run underlens.yml gh run watch

Nothing gets reviewed. Each string in reviewers and judge gets its own row: Underlens checks its secret, signs in to its harness on exactly that model, and asks for a one-word answer. The rows land in the run's summary, and the run fails until every row is ready. A missing secret, a spent sign-in or a model the CLI doesn't take shows up in its row, and the summary says whether step 3 took. Run it again after every change to underlens.config.js.

From then on

  • Every PR gets its Underlens section once it's reviewed, on the triggers your workflow lists.
  • To review a PR right away, or review it again: Actions → Underlens → Run workflow, with its branch under "Use workflow from", or gh workflow run underlens.yml --ref <branch>. Each review starts fresh and closes the fixes left open from the last one.
  • The schedule skips draft PRs until they're ready for review. PRs from forks aren't reviewed, because the fixes need a branch in your repo.
  • Fix PRs opened by the workflow don't trigger your other workflows, which is GitHub's rule for its token. Your CI runs once you merge the agreed fixes into your PR.
