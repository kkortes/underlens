Why this way

Your rules, not a model's taste

Generic AI review is loud because it has no standard to hold code to. Here every point names a rule a person wrote, so it can be checked and argued with.

Drift can't hide

A dismissed comment is gone for good. A disagreed point comes back on every scheduled run until you fix the code or change the rule, so the document and the codebase can't quietly drift apart.

Several reviewers, one voice

Different models catch different things. The judge folds overlapping findings into one point, so you get broader coverage without reading the same point three times.

Decisions, not threads

Each point comes with a fix that's already written. Taking it is one tick, and turning it down is one tick. Nothing merges into your PR unless you agree to it.

Out of the way

Reviews run on the schedule you pick, so set it for when your subscription quotas sit idle and nobody is waiting on CI. The report is there when you next open the PR.

Nothing to host

It's an npm package your workflow runs, and GitHub holds all the state: the PR description, the branches and the fix PRs. Removing Underlens means deleting three files.
